# Existing Site Migration Source Gate - June 18, 2026

## Lesson

When Louis asks to migrate an existing rep-owned website into Sparkle Suite, do not start from screenshots alone if he expects an exact or near-exact result. The source code, project export, repository, or builder package is the intake gate.

Screenshots and live URLs are comparison references. They are not enough to preserve the site faithfully unless Louis explicitly accepts a close recreation.

## What Happened

The Mile High Fizz migration initially drifted toward a generic Amethyst/Black Diamond interpretation. It was recognizable, but it was not the same MileHighFizz.com site with Sparkle Suite automations inserted.

The work became faithful only after Louis provided the Ready.ai/Readdy project source at:

`C:\Users\louis\Downloads\project-8286539 (1)\`

That source revealed the real page structure, copy, hero treatment, assets, dependencies, and original Join-page language. It also preserved the hero video, which carried much of the Mile High Fizz brand identity.

## Correct Mental Model

The target is:

Same rep website, with Sparkle Suite automations built in and styled to match.

The target is not:

- A generic Amethyst skin.
- A Black Diamond recolor.
- A "recognizable enough" approximation.
- A separate implementation of the automations.

## Practical Rules

- Ask for the source code/project export/repository first.
- Ask one question at a time.
- Use the live URL and screenshots as visual comparison, not as the primary build source.
- Preserve original brand, copy, media, typography, mood, and section hierarchy.
- Keep Sparkle Suite automations functionally standard.
- Style Trade Board, Live Queue, Calendar, Join, and tickers to match the rep brand.
- Keep the rep workspace standard unless Louis explicitly asks for a custom workspace.
- Let Nic-Nac manage migrated copy/branding through normal Site Settings unless a section is intentionally locked.
