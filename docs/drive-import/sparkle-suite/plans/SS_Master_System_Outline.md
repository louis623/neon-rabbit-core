## Section 1 — Tools and Integrations

Every tool in the Sparkle Suite system and what it does.

**neonrabbit.net/sparklesuite** — Public-facing landing page. Entry point for all new client leads. Contains the Cal.com scheduling embed.

**Cal.com** — Meeting scheduling and client intake. Embedded on the landing page. Client picks a date and time based on live calendar availability. Collects intake data before the meeting is confirmed. Auto-generates the Google Meet link. Auto-places the event on the host's Google Calendar. Sends a notification email with all collected intake data.

Cal.com intake form collects: meeting date and time, client name, email address, phone number, current website URL if any, TikTok or social media show names, and Linktree URL.

**Google Meet** — All client meetings. Auto-generated by Cal.com. All meetings are AI transcribed. Transcripts are processed by the agent after each call.

**Google Calendar** — Meeting placement only. Auto-populated by Cal.com. Will be phased out for show scheduling once the internal platform calendar is live.

**AI Transcription** — Runs on every Google Meet call. Captures all meeting content automatically. Agent reads transcripts to extract client data, intent signals, and feedback from every call.

**Supabase** — Central database and source of truth for everything. Stores all client records, status fields, build history, workflow state, and platform data. Replaces browser localStorage from the current dashboard. Not yet set up — Phase 2 first task.

**SignWell** — User agreement management and digital signing. Agent sends agreements automatically. Signed copies filed and distributed to both parties. SignWell webhook updates Supabase when agreement is signed.

**Stripe** — All payment processing. Handles start work fee, launch fee, and monthly recurring subscription. Stripe webhooks update Supabase automatically when payments are confirmed. No manual payment checking required.

**Sparkle Suite Builder Dashboard** — Central build workflow tool. Currently a standalone HTML file. Becomes a native platform module in Phase 2. Runs all client builds through Steps 1 through 5.

**Readdy.ai** — Current site building platform. Being phased out. Last two builds — Bri's Glowtique and Bling Kitchen — complete on Readdy. All future client sites built on the Neon Rabbit platform directly.

**Google Apps Script** — Current calendar middleware. Connects client Google Calendars to their websites. Being phased out when the internal platform calendar is built in Phase 2.

**Google Search Console** — SEO indexing submission. Used in post-launch Step 5 for every site.

**Bing Webmaster Tools** — Covers Bing, DuckDuckGo, Yahoo, Ecosia, and AOL. One submission covers all. Used in post-launch Step 5 for every site.

**Vercel** — Hosting for all Neon Rabbit projects. Connected to GitHub. Auto-deploys on every push to main.

**GitHub** — All code repositories under the Neon Rabbit account. louis623/sparkle-suite is the main repo.

**Next.js** — Framework for all new sites and the platform itself.

## Section 2 — Client Status Flow

Every client record in Supabase has a status field. The agent reads this field to know what action to take next. A human operator reads it to see where every client stands at a glance.

| Status | Meaning |
|---|---|
| `lead_intake` | Cal.com booking received, client record created, intelligence report being generated. |
| `pending_agreements` | Intent confirmed after discovery call. Waiting for signed agreement and start work fee. Both required before work begins. |
| `build_active` | Both gates cleared. Foundation build in progress. |
| `checkpoint_branding` | Foundation build complete. Branding review meeting scheduled or in progress. |
| `build_detail` | Branding approved. Detail build in progress. |
| `checkpoint_detail` | Detail build complete. Detail review meeting scheduled or in progress. |
| `build_finalize` | Detail feedback implemented. Final build and SEO work in progress. |
| `checkpoint_prelaunched` | Everything complete. Pre-launch inspection meeting scheduled or in progress. |
| `pending_launch_payment` | Pre-launch inspection passed. Waiting for launch fee and recurring subscription payment. |
| `launch_ready` | Both launch payments confirmed. Cleared to go live. |
| `live` | Site launched. Welcome email sent. Client fully onboarded. |

## Section 3 — Pre-Meeting Client Intelligence Report

**Trigger:** Cal.com booking webhook fires.
**Completed by:** Agent, automatically.
**Delivered:** Before the discovery call.
**Purpose:** You walk into every discovery call already knowing who the client is, what they have, and what they need.

The moment a client books, the agent researches everything publicly available and compiles a one-page brief. You receive a notification with a link to the report.

**What the agent researches:**

- **From their current website** — overall design style, color palette, fonts, layout feel, what pages exist, what is missing, existing SEO signals, mobile friendliness, screenshot captured for reference.
- **From their Linktree** — every link they are currently sending traffic to, how they position themselves, which platforms they prioritize, profile photo and any existing branding.
- **From their TikTok** — follower count, posting frequency, recent show titles and overall vibe, bio copy and how they describe themselves, profile aesthetic and tone, brand consistency assessment.
- **From other discoverable social platforms** — Facebook, Instagram, YouTube, cross-platform brand consistency.
- **From Bomb Party community pages if findable** — any reviews or mentions, community activity level.

**Report output:** client snapshot, current brand audit with dominant colors and fonts and style, audience size estimate across platforms, branding direction recommendations based on existing presence, talking points for the meeting, gaps and opportunities Sparkle Suite fills for this specific client, and a quick comparison to similar Bomb Party rep sites.

## Section 4 — Full Client Pipeline

### Stage 1 — Lead and Discovery
**Status:** `lead_intake` | **Human touchpoint:** Discovery call — you

Client lands on neonrabbit.net/sparklesuite. Cal.com embed handles everything. Client answers intake questions, picks a meeting time, Google Meet is generated, event placed on your calendar, and you receive a notification email with all intake data.

Agent reads Cal.com data and pre-populates the client record in Supabase before the call. Agent generates the Pre-Meeting Intelligence Report. You review it before the call.

Discovery call runs 30 to 45 minutes on Google Meet. AI transcribes the entire call.

After the call the agent processes the transcript, completes the client record, and listens for the intent signal — the client stating they want to move forward. If intent is confirmed, Stage 2 triggers automatically. Client status updates to `pending_agreements`.

---

### Stage 2 — Agreements and Start Work Fee
**Status:** `pending_agreements` | **Human touchpoint:** None — fully automated
**Gate:** Work does not begin until both conditions are confirmed in Supabase.

Two things go out simultaneously the moment intent is captured from the transcript.

**SignWell — User Agreement.** Agent sends the user agreement to the client's email via SignWell. Agreement covers:
- Domain ownership — Neon Rabbit retains control of any domains purchased on the client's behalf.
- All generated and built materials are owned by Neon Rabbit until the full payment relationship is active.
- Client-provided materials remain the client's property.
- Full cost structure including start work fee, launch fee, monthly recurring, and add-on rates.
- Cancellation and refund policy — start work fee is non-refundable.

Client signs digitally. Signed agreement filed in SignWell. Copy sent to both parties. SignWell webhook updates Supabase — agreement confirmed.

**Stripe — Start Work Fee.** Agent sends Stripe payment link for the start work fee to the client's email. Fee is non-refundable. Provides skin in the game and prevents mid-process abandonment. Stripe webhook updates Supabase — payment confirmed.

When both are confirmed, client status updates to `build_active` and the agent notifies you that the client is cleared and the build can begin.

---

### Stage 3 — Foundation Build
**Status:** `build_active` | **Human touchpoint:** None — agent executes dashboard workflow

Agent runs the client through Builder Dashboard Steps 1 through 4.

- **Step 1** — Client setup. Name, Calendar ID, platforms, handles, heading and subheading text, event image keyword mapping entered and saved to client record.
- **Step 2** — Apps Script generated and deployed to Google Apps Script.
- **Step 3** — Endpoint tested and verified.
- **Step 4** — Embed generated. Two Readdy prompts fired in order. Agent waits for confirmation between each.

Site foundation is live. Agent schedules Checkpoint 1 — Branding Review. Client status updates to `checkpoint_branding`.

> **Note:** In Phase 2 this stage changes significantly. The internal platform calendar replaces Google Calendar and Google Apps Script. Steps 2 and 3 are eliminated. The site reads show data directly from Supabase. The embed is no longer needed — the component is native to the platform.

---

### Checkpoint 1 — Branding Review
**Status:** `checkpoint_branding` | **Human touchpoint:** You and client on Google Meet — AI transcribed

You and the client review the site foundation together. Is the direction right? Does the branding feel correct? You give design input or approve. Meeting transcribed. Agent processes transcript, logs all feedback to the client record, and continues the build. Client status updates to `build_detail`.

---

### Stage 4 — Build Out
**Status:** `build_detail` | **Human touchpoint:** None

Agent implements all branding feedback from Checkpoint 1. Develops finer details and content. Agent schedules Checkpoint 2 — Detail Review. Client status updates to `checkpoint_detail`.

---

### Checkpoint 2 — Detail Review
**Status:** `checkpoint_detail` | **Human touchpoint:** You and client on Google Meet — AI transcribed

You and the client review finer details together — copy, layout, features, anything needing adjustment. Meeting transcribed. Agent processes transcript, logs all feedback, and implements refinements. Client status updates to `build_finalize`.

---

### Stage 5 — Finalize and Refine
**Status:** `build_finalize` | **Human touchpoint:** None

Agent implements all feedback from Checkpoint 2. Runs the full Post-Launch SEO and GEO checklist (see Section 5). Everything buttoned up and ready for final inspection. Agent schedules Checkpoint 3 — Pre-Launch Inspection. Client status updates to `checkpoint_prelaunched`.

---

### Checkpoint 3 — Pre-Launch Inspection
**Status:** `checkpoint_prelaunched` | **Human touchpoint:** You and client on Google Meet — AI transcribed

Full walkthrough of every feature and tool together. Calendar sync, stream buttons, copy buttons, Add to Calendar, discount codes, SEO work — everything verified live. Client verbally signs off.

Immediately after the meeting the agent sends the pre-launch email containing:
- Stripe payment link for the launch fee
- Stripe payment link for the monthly recurring subscription
- A preview of everything the client is about to receive upon payment

The email makes clear that portal login credentials, calendar guide, automation details, and all onboarding materials are delivered only after payment is confirmed. Nothing is unlocked yet. Client status updates to `pending_launch_payment`.

---

### Stage 6 — Launch Payment Gate
**Status:** `pending_launch_payment` | **Human touchpoint:** None — fully automated

Launch fee confirmed via Stripe webhook. Monthly recurring subscription activated and confirmed via Stripe webhook. Both confirmed — client status updates to `launch_ready`. Agent notifies you that the client is cleared to launch.

---

### Stage 7 — Launch
**Status:** `launch_ready` | **Human touchpoint:** Post-launch email review and approval — you

Domain pointed and site goes live. Agent runs final verification — live data loads, timezone correct, stream buttons working, copy buttons working, Add to Calendar working, all features confirmed.

Agent generates the post-launch email containing:
- Site is live with URL confirmed
- Plain English summary of all SEO and GEO work completed
- Calendar guide
- Portal login credentials
- All automation details
- Monthly maintenance overview
- Support contact

You review and approve. Agent sends it. Client record marked live. Build saved to history.

## Section 5 — Post-Launch SEO and GEO Checklist

Standard for every site. Every item. No exceptions.

**Traditional SEO:**
- Custom title tag on every page
- Custom meta description on every page
- Canonical URL on every page
- robots.txt live with all pages set to crawlable
- sitemap.xml live and submitted to Google Search Console
- Open Graph tags on every page for social sharing previews
- Twitter/X card meta tags
- Favicon uploaded and set
- Google Search Console — site added, sitemap submitted, indexing requested for each page
- Bing Webmaster Tools — site added, sitemap submitted (covers Bing, DuckDuckGo, Yahoo, Ecosia, and AOL all at once)

**AI Discoverability and GEO:**
- llms.txt created and live at /llms.txt — includes who the rep is, what they sell, show schedule, Bomb Party glossary, and how a live reveal works
- AI crawlers explicitly welcomed in robots.txt — GPTBot, PerplexityBot, Claude-Web, ChatGPT-User, anthropic-ai

**Schema.org Structured Data:**
- WebSite schema
- Organization schema
- Person schema — rep's full name, title, bio, social links, expertise topics, connection to the business
- Event schema — one per recurring show
- FAQPage schema
- AboutPage schema
- CollectionPage schema
- BreadcrumbList schema

**Optional upgrades based on client situation:**
- Rating and Review schema — if the rep has testimonials, enables star ratings in Google results
- Video schema — for TikTok embeds, enables Google Video tab appearances
- LocalBusiness schema — if the rep does any in-person events

> **Dashboard Step 5** — this entire checklist will be built into the Builder Dashboard with a Copy Prompt button for each item. Each button generates a pre-filled prompt ready to paste into Readdy.ai or the platform AI. Architecture is agent-ready — when an agent is active it works through this checklist autonomously, firing each prompt in order and marking items complete.

## Section 6 — Correspondence Map

Every automated email or communication in the pipeline and when it sends.

| Email | Trigger |
|---|---|
| Post-booking confirmation | Sends immediately after Cal.com booking. Confirms meeting details and sets expectations for the discovery call. |
| Pre-meeting intelligence report notification | Sends after the report is generated. Contains a link to the client brief for your review before the call. |

| Launch cleared notification to you | Sends when both launch payments are confirmed. |

## Section 8 — Payment Gates

**Gate 1 — Start Work Fee**
Requires: User agreement signed via SignWell AND start work fee received via Stripe.
Unlocks: Build begins.
Fully automated via webhooks. No manual checking.

**Gate 2 — Launch Fee and Recurring Subscription**
Requires: Launch fee received via Stripe AND monthly recurring subscription activated via Stripe.
Unlocks: Site launch and delivery of all credentials and onboarding materials.
Fully automated via webhooks. No manual checking.

## Section 9 — Phase 2 Platform Impact on This System

This section documents how the current workflow changes when the Phase 2 platform is live. Many current processes exist only because the platform does not exist yet. They will be replaced or eliminated.

| Current | Phase 2 Replacement |
|---|---|
| Google Calendar dependency | Eliminated. Internal platform calendar built in Supabase. Reps enter show schedules through the portal. Sites read directly from the database. |
| Google Apps Script | Eliminated. No middleware needed when the calendar is native to the platform. |
| Dashboard Steps 2 and 3 | Eliminated or significantly revised. No script to generate or deploy when the calendar is internal. |
| Readdy.ai | Eliminated. Sites built directly on the Neon Rabbit Next.js platform. Template cloned and deployed per client. No prompts fired into a third-party builder. |
| Browser localStorage for build history | Eliminated. All client data lives in Supabase. Accessible from any device, never lost. |
| Standalone HTML dashboard | Replaced. Dashboard becomes a native module inside the platform with full Supabase integration. |

The pipeline structure — human touchpoints, payment gates, correspondence map — remains the same. Only the build tooling changes.
